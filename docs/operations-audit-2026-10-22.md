## 发现与处理

### 第二套假在线

修复前容器运行正常，`GetAccountInfo.userId` 非空，但进程没有上游 `139.196.171.27:7190` 连接。真实登录请求返回 `data=false`，提示“服务器响应超时”。第二套已知最新消息停在 9 月 29 日；`GetOssConfig` 返回 `success=true,data=null`。

容器网络内 TCP 探测可达，说明不能直接归咎密码、授权或防火墙。完成第二套数据库备份后，仅重启第二套服务端。随后自动登录明确成功，上游 TCP、业务 HTTPS 和 MySQL 连接重新建立，同一联系人获取 OSS 配置恢复正常。这修正了之前仅根据账号缓存和容器状态认为登录正常的判断。

两套自动登录增加 `docker-control/login-state.json`：记录时间、成功/拒绝/网络错误/上游超时、连续超时次数和恢复次数，不记录凭据。连续三次明确上游超时且 TCP 可达时请求进程恢复；间隔至少 15 分钟，每次成功登录前最多两次。人工退出、普通授权拒绝、TCP 不通不触发此恢复。这个保护针对本次已复现的超时，不能保证处理所有原生服务端故障。

### 第二套备份连接超时

备份配置仍指向 NAS 局域网地址 `192.168.9.83:3306`，从第二套备份容器连接超时。服务端已使用 `host.docker.internal`，但备份/控制/自动登录容器缺少 host-gateway 映射。

修正第二套 `compose.yaml`、`docker-compose.yml` 的映射；通过原有控制模块保存备份数据库 host，保持 JSON 与 `.env` 同步。只重新创建相关辅助容器。备份目录仍为用户指定飞牛云盘 `youliaobackup-2`，没有改为本地目录。

验证导出文件 `youchat-youchat2-20261022-163018.sql.gz`，大小 160,746 字节，解压完整读取 733,923 字节。主套当日原有定时备份成功，约 86.6MB。

### 主套日志无限增长

主套 `api-capture.ndjson` 达 14,770,532,280 字节，数据盘 94% 使用率。大量列表轮询持续保存重复的聊天/联系人响应。

新增 `capture-log.js`：每文件 32MiB，当前文件加三代轮转，正常总量约 128MiB。成功的四类高频轮询只记录条数、总量、响应字节和请求耗时；失败请求、业务失败及发送/上传仍保留现有脱敏诊断。轮转前遗留的超大文件另行保留，不自动删除。

历史日志先改名冻结，新请求继续写新文件；压缩至原有飞牛云盘，完整解压后比较 SHA-256 与字节数，成功后才移除冻结原文件。归档由 `scripts/archive-capture-log.py` 执行，失败时保留原件。

### SignalR 告警与编号

主套日志大量出现未注册 `msgnotice`、`timeoutnotice` 等客户端处理器告警，掩盖实际故障。补齐本次日志确认的八类通知监听，仅记录次数/类型/时间，不保存客户正文，不由通知触发重复发送。未知事件仍保留警告。

两套 10 月 20 日 20:01 左右都曾把 19 位平台用户 ID 作为客服编号登记。主套随后有多次 `Int32` 会话绑定溢出及发送路径空引用；近期两天没有发现该错误继续出现。时间相关性和类型契约证明错误登记必须拦截，但没有原生 C# 源码，不能断言所有旧异常都只有这一个原因。

浏览器仅使用已解析的客服短编号，取消平台账号回退。服务端 online/offline/consume 和 RegisterUser 边界都限制为正 Int32，错误值直接返回 400。心跳由 120 秒改为 15 秒，保留原来的断线重连及重入组流程。

### 其余模块

检查时两套均为 MySQL，未发现近两天切 SQLite、MySQL 崩溃或容器 OOM。主套仍有实时消息写入。PromptWorks 四个容器未见最近错误。主机约 6GB 内存、交换区使用较高，属于后续容量关注项；没有据此删除数据库或重启无关容器。

### 第二套腾讯 COS 配置与欠费阻断

登录恢复后第二套实际返回 `cloudType=1` 的腾讯 COS 配置，与主套七牛不同。旧 Web 没有识别 `txHostUrl`，也没有映射 `txPolicy/txQak/txQkeyTime/txQsignature`，因此单纯拿到配置仍无法上传。

浏览器与 Node 代理补齐腾讯 PostObject 的 `policy`、`q-sign-algorithm=sha1`、`q-ak`、`q-key-time`、`q-signature`，保留七牛行为。用第二套自己的配置及 2,463,841 字节指南图请求 COS，服务明确返回 HTTP 451、`UnavailableForLegalReasons`，错误正文说明账户欠费、充值前不可用。

增加明确的存储欠费提示；存储服务明确返回不可重试的 4xx 时，浏览器不再启动第二次直传。图片和文字草稿仍保留。此项需要悠聊服务商恢复该 COS 存储账户后才能完成真实成功上传验收，不能用第一套凭据或更换客户数据归属来掩盖。

主套原始 2.46MB PNG 在本轮复测也有一次 60 秒超时。同内容 400,254 字节 JPEG 约 4.57 秒成功。大促服务端上传原先没有使用浏览器压缩，现增加单独 JPEG 上传副本，原 PNG 继续保留预览；不把一次小图成功当成上传网络永远正常。

首次安装登录检测重启辅助容器时，主套旧脚本的 mysql 启动模式触发了两次原生进程重载。安装器已加一次性跳过数据库初始化的标记，后续更新此补丁不再顺带执行数据库初始化；运行期间的 MySQL 检查保留。

## 维护入口

设置环境变量 `FNOS_PASSWORD`，必要时设置 `FNOS_SUDO_PASSWORD`；不要把密码写入提交。

```powershell
npm run check
npm run test:operations
python scripts/audit-fnos-logs.py --hours 48 --max-mib 1024
python scripts/repair-fnos-youchat-sidecars.py
python scripts/install-fnos-login-health.py
python scripts/deploy-fnos-web-all.py
```

备份修复依赖飞牛宿主机现有 PyYAML。`tests/login-health.sh` 在 Linux 使用模拟登录结果验证触发次数、冷却、上限、网络失败和人工暂停，不连接客户或发送消息。

客户端 Docker 新增复制 `capture-log.js`；浏览器在 `app.js` 前加载 `signalr-policy.js`。部署打包排除临时 SSH 探针和 Python 缓存，保留两套运行数据隔离。
